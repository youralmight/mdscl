# 课程仓库同步

在 **mdscl 仓库根目录** 执行：

```bash
uv run --project ../uv_base python tools/repository-sync/sync.py
```

这一个命令从远端发现并同步**全部配置来源**，不上传本地内容。需要 `uv`、`git`、旁边的共享 Python 项目 `../uv_base` 和远端访问权限；不需要另外运行规划或 Git 执行脚本。

## 会不会覆盖本地文件？

| 仓库 | 已有仓库的更新行为 |
| --- | --- |
| 当期官方材料 | fetch 后，本地提交与远端目标提交不同时执行 **`reset --hard`**，覆盖已跟踪文件的本地修改，并将当前分支提交位置对齐远端。提交未变时保留本地修改并警告。 |
| 个人作业 | **只 fetch**：获取远端提交，不改变本地分支、当前提交、暂存区或工作区。需要自己合并更新。 |
| 公开历史材料 | 按官方材料规则更新，但**只更新本地已有 `.git` 目录的保留仓库**，不重新下载已删除的历史仓库。 |

缺失的当期材料和个人作业仓库会自动 clone。没有额外清理操作；但官方材料执行 hard reset 时，挡住检出路径的未跟踪内容仍可能被删除。不要在官方镜像里保存需要保护的工作。

接口只接受标准 `--help`，不提供来源选择、离线、只刷新清单或强制清理模式。**作业只 fetch 不等于只同步作业**：每次运行仍包括官方材料。

## 同步哪些来源、放在哪里？

`sources.conf` 是来源和筛选策略配置，一行一个来源：

```text
name ; api_base ; org ; include ; exclude ; family ; mode
```

`include` / `exclude` 是 Python 正则；空 include 不限制，空 exclude 不排除。`family` 决定目录分类，`mode` 决定 Git 操作（`mirror` 对齐官方材料；`work` 保留个人工作）。

当前活动范围是 **Block 2：DSCI 512、531、552、571**，官方材料、个人作业和公开镜像五条来源都限定在这四门课。以后换 Block，修改各行 `include` 中的课程号即可；保留各来源的 `_students`、`_yz2000` 限制和 512 来源排除规则，不需要改 `sync.py`。

当前来源：

- UBC GitHub 的 `mds-2026-27`：当期材料和 `_yz2000` 个人作业，排除 DSCI 512。
- UBC GitHub 的 `MDS-CL-2026-27`：活动课程的 `_students` 教学仓库，以及 `_yz2000` 个人作业。**DSCI 512 的当期材料和作业只从这里获取。**
- github.com 的 `UBC-MDS`：活动课程的公开材料，只更新本地保留的历史镜像。

```text
<课程号>/official/current/<仓库名>
<课程号>/official/public/<仓库名>
<课程号>/assignments/<作业名>/<仓库名>
```

例如，个人仓库 `DSCI_512_lab1_yz2000` 放到 `DSCI_512/assignments/lab1/DSCI_512_lab1_yz2000/`。

Block 1 的 511、521、523、551 放在 `archived/block 1/`。归档只是目录整理；停止更新靠 `sources.conf` 的活动范围，而不是脚本自动识别归档目录。当前配置不会 fetch 这些旧课，也不会在根目录重新 clone；以后若重新启用某门旧课，脚本仍按上面的根目录路径同步，不会直接更新归档副本。

API 查询从 `~/.git-credentials` 读取对应主机的 token；Git clone/fetch 使用 Git 自身的认证配置。程序不打印 API token。

## 三个清单文件

`current.txt`、`work.txt`、`public.txt` 分别列出当期材料、个人作业和公开材料的仓库 URL，一行一个地址。每次成功完成发现、规划和 origin 检查后生成，**只供查看，不是同步输入或成功记录**。

`public.txt` 可以包含本地没有保留的历史仓库；列入清单不代表会下载。手工删除清单中的地址不能永久排除仓库，应调整 `sources.conf` 的规则。

## 出错时怎么处理？

程序先发现全部来源、规划目录、检查已有仓库，再发布清单和更新 Git：

- **配置、API 或目录冲突出错：整次停止。** 不更新目标仓库，不发布新清单；报出出错来源、目录或原因。
- **已有目录不是 Git 仓库，或 origin 不匹配：整次停止。** `origin` 是该本地仓库记录的远端地址；更新前核对它是否对应配置中的那个仓库。不会自动改 origin、换组织或删除占位目录。
- **清单写入或发布失败：停止，不进入 Git 更新。** 先暂存完整清单再逐文件发布；发布不是三个文件一起的事务，失败时部分清单可能已更新。
- **某个仓库 clone/fetch/reset 失败：记录 Git 错误，继续其余仓库。** 最后汇总失败项，返回非零退出码。已完成的更新不回滚，清单也可能已发布。

HTTP 和 Git 操作都有超时，不自动重试或回退来源。修复报出的原因后，可以重新运行同一个同步命令。
