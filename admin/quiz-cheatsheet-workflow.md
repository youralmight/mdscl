# Quiz 知识文档与 Cheat Sheet 工作规范

## Intent

先为每门 Quiz 建立一份准确、完整、简洁的知识底稿，再由用户与课程 Agent 交互式决定哪些内容进入 Cheat Sheet。不要在不了解用户掌握情况时直接生成一页纸，也不要在内容选择完成前决定图片和排版工具。

## 当前分工

本 Block 只有三门需要正式 Quiz；每个 Agent 只负责一门课程：

| Agent 负责范围 | 完整知识文档 | 后续内容稿 |
|---|---|---|
| DSCI 511 | `DSCI_511/notes/quiz1-knowledge.md` | `DSCI_511/notes/quiz1-cheatsheet.md` |
| DSCI 523 | `DSCI_523/notes/quiz1-knowledge.md` | `DSCI_523/notes/quiz1-cheatsheet.md` |
| DSCI 551 | `DSCI_551/notes/quiz1-knowledge.md` | `DSCI_551/notes/quiz1-cheatsheet.md` |

DSCI 521 没有正式 Quiz，不在本次范围内。`official/` 是只读材料；Agent 只能写自己课程的 `notes/` 文件。Quiz 2 后续沿用同一规范，文件名改为 `quiz2-*`。

## 阶段一：完整知识文档

### 目标

`quiz1-knowledge.md` 是本次 Quiz 的课程知识 SoT。它不受一页纸限制，也不针对用户当前水平做删减。这里的“完整”指覆盖全部可考知识，而不是逐段复述讲义。

### 来源顺序

按以下优先级确定本学期的考试范围和知识内容：

1. 本学期教师明确发布的 Quiz logistics、范围和题型说明
2. 本学期 `official/current/` 中的 learning objectives、lecture notes 和 slides
3. 本学期 practice quiz、worksheet 和 lab
4. 课程 `notes/messages.md` 中的教师通知或勘误
5. `official/public/` 历史材料只能帮助解释当前材料，不能覆盖本学期说明；使用时必须标记为历史参考

遇到冲突时保留高优先级来源，并在知识文档中明确记录冲突。无法确认的内容标为 `[未确认]`，不得猜测。

### 文档结构

每份知识文档使用以下结构：

```markdown
# DSCI XXX Quiz N Knowledge

## Scope and assessment contract
## Coverage map
## Lecture/topic sections
### K001 — Atomic knowledge point
## Coverage audit
## Sources
```

要求：

- `Scope and assessment contract`：记录 lecture 范围、已公布题型、允许工具、指定方法和评分限制；没有证据的项目写 `[未确认]`。
- `Coverage map`：把每个 learning objective 映射到知识点编号。
- 每个知识点使用稳定编号 `K001`、`K002`……；后续即使调整顺序也不要改号。
- `Coverage audit`：列出每个 learning objective 和明确可考主题是否已经覆盖。
- `Sources`：记录实际使用的本学期文件、章节或官方链接。

### 原子知识点要求

一个编号只表达一个可独立选择进入 Cheat Sheet 的知识点。根据内容需要，从以下字段中选择有用的字段；不要创建空字段：

- 核心概念或规则
- 什么时候使用，以及如何判断
- 公式和符号定义
- 函数签名、关键参数与默认行为
- 输入、输出和返回类型
- 最小可运行示例或最小计算例
- 常见错误、边界情况和易混淆对比
- 对应 learning objective 和来源

课程差异：

- R/Python 内容重点记录函数用途、参数、返回对象、指定方法和最小代码模板。
- 概率与统计内容重点记录公式、符号含义、适用条件、判断步骤和一个最小例子。
- 对比型内容优先使用表格；流程型内容优先使用短步骤；不要用长篇叙述替代结构。

### 完整性标准

第一阶段必须满足：

- 每个明确公布的 learning objective 至少映射到一个知识点编号。
- 每个 lecture 中未标为 optional 且在 Quiz 范围内的主题均有覆盖。
- 教师明确强调的题型、方法限制、返回类型和常见失分点均有记录。
- Practice quiz、worksheet 和 lab 用于发现考法与易错点，但不因它们更深入而擅自扩大考试范围。
- 示例足以说明规则，但不复制整道练习题，也不堆叠表达同一规则的重复例子。
- 没有把用户可能已经会的内容删掉。

### 简洁性标准

- 一个概念只在一个位置完整解释，其他位置用知识点编号引用。
- 每个知识点默认只保留一个最小例子。
- 删除课堂叙事、鼓励性文字、重复定义和与考试无关的背景。
- “简洁”只能减少表达成本，不能减少可考知识。

### 第一阶段停止条件

完成并审查 `quiz1-knowledge.md` 后停止。向用户报告：

- 文档路径
- 覆盖的 lecture 和 learning objectives
- 使用的主要来源
- 所有 `[未确认]` 项

在用户开始选择内容以前，不创建 Cheat Sheet，不做一页排版，也不生成图片。

## 阶段二：交互式选择 Cheat Sheet 内容

### 原则

Agent 不猜用户会什么。用户决定收录、删除和展开哪些内容；Agent 负责准确录入、压缩表达、发现依赖和防止遗漏。

用户可以直接引用知识点编号，例如：

- “把 K023 放进去。”
- “K017 我会，先不要。”
- “K031 保留，但压成一句。”
- “K042 的例子换成我更容易记住的版本。”

自然语言描述也可以；Agent 应定位对应编号，而不是要求用户记编号。

### `quiz1-cheatsheet.md` 的职责

- 它是未来图片的内容稿，不是最终视觉版。
- 只放用户已经选择的可打印内容，不复制来源说明、审计表或讨论过程。
- 使用与知识文档相同的知识点编号，便于追溯和修改。
- 用户确认必须保留的内容标为 `must`；用户希望有空间再放的内容标为 `if-space`。
- 优先使用公式、对比表、判断规则、代码模板和短提示，不把知识文档中的解释原样整段搬入。

### 交互规则

- 用户要求加入内容时，先忠实加入，再做不改变含义的压缩。
- 用户要求删除内容时，不得在后续整理中自行放回。
- 如果删除某项会让另一项难以理解，指出具体依赖关系，由用户决定，不替用户做决定。
- 不因 Agent 认为某内容“太基础”而删除，也不为了显得完整而重新加入用户明确不要的内容。
- 每次编辑保持现有选择和措辞偏好；`quiz1-cheatsheet.md` 本身就是当前选择状态。
- 图片尚未确定尺寸分栏前，不以猜测的页面容量强行删内容。容量冲突先通过 `must` 与 `if-space` 表达。

## 阶段三：图片与页面排版

当前不执行。等用户确认 `quiz1-cheatsheet.md` 的内容后，再单独决定：

- Markdown 到 PDF/PNG 的工具链
- Letter 单面页面的列数、字号和留白
- 代码、公式和表格的视觉层级
- 如何在至少 8 pt 且打印可读的前提下填满页面
- 最终 PNG 是否不超过 PrairieLearn 的 5 MB 限制

不要让尚未决定的渲染工具反向限制第一阶段知识文档或第二阶段内容选择。

## Agent 交付边界

- 一个 Agent 只编辑自己课程的两个 `notes/` 文件，不触碰另外两门课程。
- 不修改、整理或补写 `official/`。
- 不把历史材料当成本学期考试事实。
- 不直接从完整知识文档自动生成最终 Cheat Sheet。
- 不生成图片，除非用户之后明确启动第三阶段。
- 发现范围、来源或教师要求不一致时，先完成所有可确认内容，再把具体冲突交给用户判断。
